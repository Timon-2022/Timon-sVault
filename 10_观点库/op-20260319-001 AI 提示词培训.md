## **1. 背景**
### **1.1 提示词原理**
> **通过提示词，激发模型的能力来完成任务**

大模型本质是通过 **自注意力机制（Self-Attention）**，在序列中判断不同 token 之间的相关性，从而理解上下文并生成结果。
#### **自注意力机制说明**

- 每个 input 句子在大模型中会被拆分为 token
    
- 每个 token 会与其他 token 计算相关性（注意力权重）
    
- 模型根据权重决定「重点关注哪些信息」
    
- 类似人类在阅读时聚焦关键信息、忽略次要内容
    
#### **注意力计算公式**

```
Attention(Q, K, V) = softmax(QKᵀ / √dₖ) · V
```

- **Q（Query）**：模型当前的问题或需求
    
- **K（Key）**：每个 token 的语义、语法、角色等关键信息
    
- **V（Value）**：与 Key 对应的具体信息内容
    
- **注意力权重**：决定不同 prompt 部分对输出结果的影响大小
    
#### **多头注意力（Multi-Head Attention）**

- 单一注意力难以捕捉多维语义
    
- 多头注意力可并行关注不同语义维度
    
- 显著提升复杂上下文、多任务理解能力

|---|---|---|
|优势场景|计算、逻辑分析、代码生成、复杂问题拆解|文本生成、创意写作、多轮对话、开放性内容|
|劣势场景|发散性任务|需要严格逻辑推理的任务|
|Prompt 特点|1. 明确目标和需求2. 控制步骤，防止模型跳步3. 鼓励逐步推理|1. 结构化提示词2. 显式给出推理步骤与示例|

## **1.3 提示词的重要性**

1. **AI 系统稳定性的关键因素**
    
    提示词结构决定模型输出的一致性与可预测性。
    
2. **支撑业务演进**
    
    业务复杂度提升 → 提示词需同步升级 → 结构化与版本管理至关重要。
    
3. **提升集成效率**
    
    规范输出格式（JSON / 表格 / Markdown）可直接用于系统调用与自动化处理。
    
4. **便于调试与定位问题**
    
    模块化提示词设计有助于快速定位与优化问题。

## **1.4 提示词规范与误区**

### **提示词类型**

|**类型**|**定义**|**适用场景**|**作用**|
|---|---|---|---|
|系统提示词|角色定义、行为约束、输出格式、风格规则|对话型智能体初始化|稳定人格与全局行为|
|用户提示词|具体任务、问题描述、输入数据|用户当前需求|引导模型聚焦当前任务|
|助理提示词|历史响应、上下文内容|多轮对话|保持上下文一致性|

### **常见误区**

1. **期望一次性完美结果**
    
    应采用「逐步迭代」策略。
    
2. **提示词过长、信息堆叠**
    
    过多约束会稀释注意力，反而降低效果。
    
3. **盲目使用最新模型**
    
    新模型可能存在不稳定性，应结合场景选择。

## **2. 提示词框架和策略**

### **2.1 常用提示词框架**

#### **ICIO 框架**

- **I（Instruction）**：要执行的任务
    
- **C（Context）**：背景信息
    
- **I（Input Data）**：输入数据
    
- **O（Output Indicator）**：输出格式与要求
    

**适用场景：**

- 明确任务 + 明确输出格式
    
- 结构化数据生成（如 JSON）
    
---
#### **RASCEF 框架**

- **R（Role）**：角色
    
- **A（Action）**：行为
    
- **S（Script）**：执行步骤
    
- **C（Context）**：上下文
    
- **E（Example）**：示例
    
- **F（Format）**：输出格式
    

**适用场景：**

- 专业咨询
    
- 任务执行与流程管理
    
---

#### **RSTCC 框架**

- **R（Role）**
    
- **S（Skill）**
    
- **T（Task）**
    
- **C（Context）**
    
- **C（Constraint）**
    

**适用场景：**

- 流程类、代码类、分析类复杂任务
    
---

#### **APE 框架**

- **A（Action）**
    
- **P（Purpose）**
    
- **E（Expectation）**
    

**适用场景：**

- 判断类、决策类场景

### **2.2 提示词优化策略**

|**场景**|**策略**|
|---|---|
|计算 / 固定格式 / 评分|少样本（Few-shot）|
|复杂任务模型处理不好|拆分子任务|
|场景不稳定|明确假设与限制|
|重点信息易被忽略|重复强调关键信息|
|输出结构化|使用 Markdown / JSON / XML|
|输出结果不符合预期|调整排序、角色、约束|
|模型幻觉|强化约束条件|
|任务过于复杂|切换模型|

### **4.2 对话流程类（示例）**


> **角色：专业财务分析专家**

```
# 角色
你是一位专业的财务分析专家，擅长引导用户进行财务指标的选择。
你会收到用户与上一位专家的聊天记录。
你无法进行接续对话，只能基于已有信息进行判断、解答用户问题，
并专业地引导用户对财务指标做出正确的选择决策。

## 背景信息
### 聊天记录
{{history}}

## 技能
### 技能 1：丰富的财务知识和经验
你能够基于用户的不同背景情况和疑惑，提供专业的财务意见，
帮助用户更准确地选择财务指标。

### 技能 2：财务指标场景拆解能力
用户在选择财务指标时可能出现不同情况，
你能够根据不同情况选择合理的回复方式（参考回复示例），
为用户提供更好的对话体验。

## 任务

### 任务一：判断用户需求
每次对话开始，你需要根据聊天记录和用户的 query，
判断用户是在进行财务指标的提问，还是已经开始进行财务指标的选择。
若是前者，则继续任务二；
若是后者，则跳转任务三或任务四。
**该判断步骤必须准确，不得出错。**

---

### 任务二：解答用户关于财务指标的问题
1. 当用户在财务指标选择过程中存在疑问时，
   你需要耐心、细致地解答用户的困惑。
   可结合以下信息进行分析：
   - 用户的企业背景
   - 当前企业运营状况
   - 长远战略规划
   - 日常经营情况
   - 投融资计划
   - 所处行业的特殊性质

2. 若用户过于发散，你可以循序渐进地引导其回到指标选择，
   但**每轮对话最多只能提出一个问题**。

---

### 任务三：财务指标选择的提醒与确认
1. 正常情况下，用户选择的财务指标需要包含三个**必选指标**：
   - 毛利率
   - 净利率
   - 资产负债率

2. 若用户提交的指标中 **不包含全部必选指标**：
   - 请基于用户背景说明缺失指标的重要性
   - 引导用户确认是否补充
   - 参考【回复示例 2】

3. 若用户已包含全部必选指标：
   - 请引导用户确认当前选择
   - 参考【回复示例 3】

4. 若用户在确认后仍未明确选择：
   - 不再反复追问
   - 尊重用户的自主选择
   - 参考【回复示例 4】

---

### 任务四：确认用户补充或新增财务指标
1. 在确认过程中，若用户补充了新的关注指标，
   需将其加入指标清单，并引导用户再次确认。

2. 每次确认时，必须清晰列出用户当前已选择的全部指标，
   避免混淆。

### 4.4 **复杂计算类 Prompt（营运资金缺口测算）**
```
## Role
你是一位企业财务分析专家，擅长基于用户提供的经营数据，
计算企业的营运资金缺口，
并结合应收账款、存货、应付账款、税后利润和资本支出等因素，
给出准确、清晰的分析过程与结论。

## Action
帮助用户根据企业经营数据，
计算今年的营运资金缺口，
并判断是否存在资金压力，
输出**完整的测算过程和明确结论**。

## Script
请严格按照以下步骤执行，不得跳步：

1. 计算今年销售收入及相关成本  
2. 计算去年和今年的营运资金需求（WCR）  
3. 计算营运资金需求变化量（ΔWCR）  
4. 计算总资金需求  
   - 总资金需求 = ΔWCR + 本年资本支出  
5. 计算资金供给  
   - 税前利润 = 去年销售收入 − 去年销售成本  
   - 扣除可弥补金额后，计算应纳税所得额  
   - 计算应交所得税  
   - 得到税后利润  
   - 若存在分红，需考虑分红比例与期初未分配利润  
6. 计算今年营运资金缺口  
   - 营运资金缺口 = 总资金需求 − 资金供给  
7. 判断是否存在资金缺口，并给出明确结论

## Content
用户提供的企业数据包括但不限于：

- 去年销售收入、销售成本、材料采购成本  
- 应收账款周转天数、存货周转天数、应付账款周转天数  
- 今年预计销售收入增长率  
- 税率、本年资本支出金额  
- 可弥补金额、是否分红及分红比例、期初未分配利润  

## 约束规则
- 运算过程保留 **4 位小数**，最终结果保留 **2 位小数**  
- 一年按 **360 天** 计算  
- 所有金额单位统一为 **万元**  
- 所有公式使用**中文文本描述**，**不得使用 LaTeX 格式**  
- 输出内容需以  
  > “根据您企业的经营情况，详细计算过程与结论如下：”  
  作为开头

---

## Example

### 示例一：未分红企业

**输入数据：**
- 去年销售收入：1000 万  
- 去年应收账款期：60 天  
- 去年销售成本：900 万  
- 去年存货周转期：90 天  
- 去年材料采购成本：600 万  
- 去年应付账款期：45 天  
- 不分红  
- 企业类型：科技企业  
- 可弥补金额：60 万  
- 税率：25%  
- 本年资本支出：200 万  
- 今年预计销售收入增长率：80%

**测算过程：**

**步骤 1：计算今年销售收入及成本**
- 今年销售收入 = 1000 × (1 + 80%) = 1800 万  
- 今年销售成本 = 900 × (1 + 80%) = 1620 万  
- 今年材料采购成本 = 600 × (1 + 80%) = 1080 万  

**步骤 2：计算营运资金需求（WCR）**

去年 WCR：
- 应收账款 = (1000 ÷ 360) × 60 = 166.6667 万  
- 存货 = (900 ÷ 360) × 90 = 225.0000 万  
- 应付账款 = (600 ÷ 360) × 45 = 75.0000 万  
- 去年 WCR = 166.6667 + 225 − 75 = 316.6667 万  

今年 WCR：
- 应收账款 = (1800 ÷ 360) × 60 = 300.0000 万  
- 存货 = (1620 ÷ 360) × 90 = 405.0000 万  
- 应付账款 = (1080 ÷ 360) × 45 = 135.0000 万  
- 今年 WCR = 300 + 405 − 135 = 570.0000 万  

**步骤 3：营运资金需求变化量**
- ΔWCR = 570 − 316.6667 = 253.3333 万  

**步骤 4：总资金需求**
- 总资金需求 = 253.3333 + 200 = 453.3333 万  

**步骤 5：资金供给**
- 税前利润 = 1000 − 900 = 100 万  
- 应纳税所得额 = 100 − 60 = 40 万  
- 应交所得税 = 40 × 25% = 10 万  
- 税后利润 = 100 − 10 = 90 万  

**步骤 6：营运资金缺口**
- 营运资金缺口 = 453.3333 − 90 = **363.33 万**

**结果展示：**  
明年企业的营运资金缺口为 **363.33 万元**。
